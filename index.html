When the backend goes dark, I decompile the client to figure out exactly what it still expects, then rebuild that backend from nothing. And when the client itself is missing a feature or a fix, I patch its compiled bytecode directly instead of waiting for a source that doesn't exist anymore.

What I've been rebuilding

Server revival & binary patching

2026 · ONGOING

The original C# server source for this mobile racer had been permanently deleted. I rebuilt it from zero by decompiling the production binary, got it compiling cleanly, and verified it byte-for-byte against the original with a differential test across dozens of live requests. From there I kept extending it: tournaments, a versus mode, and a custom UDP broadcast protocol so the app finds the server on any network without touching a phone's DNS. I also patched the Android client's compiled bytecode directly (IL rewriting) to restore development tooling the shipped build had stripped out, and to add a full in-game localization system the original never had.

Dead backend, reimplemented

2026 · PYTHON SERVER

When a mobile game's backend shuts down, the client doesn't stop calling it. It just gets silence back. I audited every one of its ~160 endpoints straight from the decompiled client to work out which ones actually mattered (several turned out to be dead code the client never calls), then rebuilt a matching server in Python and SQLite covering login, teams, tournaments, ghost replays and level publishing. A small desktop admin panel on top lets me manage players and levels while it's running.

Reviving a 2018 Unity build for iOS

2026 · iOS PORT

Cross-compiled an old Unity build to run natively on iOS and chased a crash that only showed up on 64-bit devices: the physics engine assumed a point was always double-precision, and arm64's calling convention broke that assumption and corrupted the vector math under the hood. Fixed the ABI mismatch, then hit a separate wall getting the result to install at all, solved by splitting the universal binary into two architecture-specific IPAs so each one could be signed for sideloading.
